#### Q1. [cite_start]Matrix Multiplication Kernels [cite: 6, 7]
[cite_start]In this chapter, we implemented a matrix multiplication kernel that has each thread produce one output matrix element. [cite: 6] [cite_start]In this question, you will implement different matrix-matrix multiplication kernels and compare them. [cite: 7]

**1. Row-fixed Design**
* [cite_start]**Description:** One thread computes one entire output matrix row. [cite: 8, 15]
* [cite_start]**Implementation:** `[Exercise_Ch3_Q1.cu]` [cite: 10]
* **Pros:**
    * [cite_start]**Simple indexing:** Each thread is responsible for one row, so no complex coordinate transformations are required. [cite: 17, 18]
    * [cite_start]**Ease of use:** This makes the kernel easy to implement and debug. [cite: 19]
    * [cite_start]**Low warp divergence:** Threads within a warp typically execute the same instructions, resulting in consistent control flow and higher warp execution efficiency. [cite: 20, 21]
    * [cite_start]**Clear thread-level parallelism:** Rows are independent, so synchronization is generally unnecessary, simplifying the kernel design. [cite: 22, 23]
* **Cons:**
    * [cite_start]**Poor memory coalescing:** Threads within a warp access elements from different rows of matrix A `A[row*K + kk]`, resulting in strided memory access and inefficient global memory transactions. [cite: 25, 26]
    * [cite_start]**Excessive global memory traffic:** Elements of matrix B are repeatedly loaded from global memory by multiple threads without being shared, leading to excessive memory bandwidth usage. [cite: 27, 28]
    * [cite_start]**Limited parallelism:** The total number of threads is bounded by the number of rows (M). [cite: 29, 30]
    * [cite_start]**Reduced performance:** If M is small, the GPU may not be fully utilized, reducing overall performance. [cite: 31]

**2. Col-fixed Design**
* [cite_start]**Description:** One thread computes one entire output matrix column. [cite: 11, 32]
* [cite_start]**Implementation:** `[Exercise_Ch3_Q1.cu]` [cite: 13]
* **Pros:**
    * [cite_start]**Good memory coalescing:** Specifically for matrix B access (`B[kk * N + col]`). [cite: 34]
    * [cite_start]**Low warp divergence:** Threads execute identical loops with minimal branching, resulting in consistent control flow and efficient warp execution. [cite: 35, 36]
    * [cite_start]**Clear thread-level parallelism:** Each column is computed independently, so synchronization is generally unnecessary and race conditions are avoided. [cite: 37, 38]
* **Cons:**
    * [cite_start]**Redundant loads:** Frequent redundant loads of matrix A (`A[row*K + kk]`). [cite: 40]
    * [cite_start]**Lack of data reuse:** Matrix data is repeatedly fetched from global memory without cooperative sharing between threads. [cite: 41, 42]
    * [cite_start]**Limited parallelism:** Total threads are approximately limited to N. [cite: 43, 44]
    * [cite_start]**No shared memory utilization:** The kernel relies entirely on global memory and does not exploit shared memory tiling, which is critical for high-performance matrix multiplication. [cite: 45, 46]
